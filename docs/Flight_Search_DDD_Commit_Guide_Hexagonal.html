1. Phạm vi & nguyên tắc

Nguồn dữ liệu: 6 bảng và các cột bên dưới trích từ milestone1.docx. Các Aggregate, VO, business methods, API, test, index và package là đề xuất triển khai — cần xác nhận trước khi Codex tạo code.

Ownership: Flight Search sở hữu flights, airports, aircrafts, fares, seats, flight_availability. Booking Service sở hữu booking, passenger selection và điều phối saga. Không ghi trực tiếp DB của service khác.

Chốt trước khi code: Fare là child Entity của Flight; Seat là root độc lập; Availability là projection. Nếu team thay đổi ownership của Seat hoặc cách giữ chỗ, phải cập nhật cả tài liệu lẫn contract.

2. Kiến trúc DDD + Hexagonal (theo mẫu job-service)

Quy ước được chọn: api là driving adapter, application điều phối use case, domain chứa business rules, infrastructure là driven adapter. Đây là cách kết hợp DDD + Ports & Adapters, không phải quy định bắt buộc của DDD. Giữ cấu trúc layer-first như mẫu và thêm folder khi thực sự cần.

api/ — đầu vào HTTP

rest/: Controller; dto/: request/response; exception/: chuyển lỗi thành HTTP. Controller validate dữ liệu đầu vào, map request thành Command/Query, gọi input port, không gọi JpaRepository.

application/ — use case

command/: dữ liệu yêu cầu thay đổi; query/: dữ liệu yêu cầu đọc; port/in/: use case interface; service/: implementation, transaction, điều phối; port/out/: output ports như query projection, publisher. Command không tự thực thi; Service thực thi use case.

domain/ — nghiệp vụ

aggregate/: Flight, Seat, Airport, Aircraft (Aggregate Root cũng là Entity); model/: Fare (child Entity), enum; valueobject/: IDs, Money, SeatNumber, ValidityPeriod; repository/: abstraction tải/lưu Aggregate; event/, exception/ khi cần.

infrastructure/ — kỹ thuật

adapter/: triển khai repository/port; persistence/entity/: JPA entities, tách biệt domain; persistence/mapper/: domain ↔ JPA; persistence/repository/: Spring Data JpaRepository; messaging/: RabbitMQ/Outbox; scheduler/: hết hạn hold; config/: cấu hình.

Cây package mục tiêu (định hướng, không tạo class rỗng)

flight-search-service/src/main/java/<base-package>/
├── api/
│   ├── rest/                  FlightController, SeatInternalController
│   ├── dto/                   Request / Response

│   ├── model/                 Fare, FlightStatus, SeatStatus, FareClass

│   ├── repository/            FlightRepository, SeatRepository, ...

Ranh giới dependency: api → application → domain; infrastructure → domain/application ports. Domain không import Spring Web, JPA, RabbitMQ. domain/repository dành cho contract của Aggregate; application/port/out dành cho query/external gateway nếu chọn cách này — không khai báo hai interface trùng chức năng.

Phân biệt: domain/aggregate/Seat là đối tượng nghiệp vụ; infrastructure/persistence/entity/SeatJpaEntity là bản ghi JPA. FlightAvailability là Read Model; lưu trong flight_availability, đọc qua Query Port/Adapter; không ép thành Aggregate Root.

Luồng gọi theo cấu trúc này

Command: Hold Seat
Booking Service → api/rest/SeatInternalController → application/command/HoldSeatsCommand → application/port/in/HoldSeatsUseCase → application/service/HoldSeatsService → domain/repository/SeatRepository → infrastructure/adapter/SeatRepositoryAdapter → JPA/MySQL

Application gọi hành vi Seat.hold() để kiểm tra rule; adapter/database đảm bảo atomicity và chống race condition. Transaction nhiều ghế phải all-or-nothing.

Query: Search Flights
api/rest/FlightController → application/query/SearchFlightsQuery → application/port/in/SearchFlightsUseCase → application/service/SearchFlightsService → application/port/out/FlightQueryPort → infrastructure/adapter/FlightQueryAdapter → Read DTO

Query có thể dùng projection tối ưu; không nhất thiết tải toàn bộ Aggregate. Nếu dùng CQRS nhẹ, không cần tạo CommandHandler/QueryHandler song song với Application Service.

Quy tắc cho Codex

Tuân theo đúng package tree trên; chỉ tạo file phục vụ commit đang làm; không tự đổi sang interfaces/ hay presentation/; không tự gộp Domain Entity với JPA Entity; không thêm bảng ngoài 6 bảng đã đặc tả. Khi gặp quyết định còn mở (schema, optimistic/pessimistic locking, outbox, tính nhất quán availability), báo rõ trước khi triển khai.

3. Đặc tả Entity, Aggregate & Read Model

Tên cột, kiểu dữ liệu và mô tả lấy từ milestone1; vai trò DDD và quy tắc nghiệp vụ là phần thiết kế bổ sung.

flights — Aggregate Root — Flight

Quản lý lịch trình, tuyến bay theo origin_code/destination_code, máy bay và trạng thái; Fare thay đổi thông qua Flight.

NoFieldData TypePKFKUNNNDescription
1idUUIDXXXUnique identifier for each flight.
2flight_codeStringXFlight number or code assigned to the flight.
3origin_codeStringXXCode referencing the departure airport (airports.code).
4destination_codeStringXXCode referencing the arrival airport (airports.code).
5departure_timeTimestamp with time zoneXScheduled departure date and time.
6arrival_timeTimestamp with time zoneXScheduled arrival date and time.
7aircraft_idUUIDXXID referencing the aircraft assigned to the flight.
8statusStringXCurrent flight status (SCHEDULED, DELAYED, CANCELLED, COMPLETED).

Business behavior (đề xuất): Hành vi đề xuất: schedule(), reschedule(), cancel(), markDelayed(), complete(), addFare(), changeFarePrice(). Kiểm tra origin ≠ destination; arrival > departure; state transition hợp lệ.

airports — Aggregate Root — Airport

Danh mục sân bay độc lập, code là duy nhất; Flight tham chiếu AirportCode thay vì giữ đối tượng Airport.

NoFieldData TypePKFKUNNNDescription
1idUUIDXXXUnique identifier for each airport.
2codeStringXXUnique airport code (e.g., HAN, SGN).
3nameStringXFull name of the airport.
4cityStringXCity where the airport is located.
5countryStringXCountry where the airport is located.

Business behavior (đề xuất): Hành vi đề xuất: register(), rename(), changeLocation(). AirportCode unique; không xóa sân bay đang được tham chiếu.

aircrafts — Aggregate Root — Aircraft

Danh mục loại máy bay và sức chứa; không có SeatDefinition trong ERD hiện tại.

NoFieldData TypePKFKUNNNDescription
1idUUIDXXXUnique identifier for each aircraft.
2modelStringXAircraft model (e.g., Airbus A321, Boeing 787).
3total_seatsIntegerXTotal seating capacity of the aircraft.

Business behavior (đề xuất): Hành vi đề xuất: register(), changeModel(), changeCapacity(). Capacity > 0; không hạ capacity thấp hơn số ghế đã gán nếu không có quy trình migration.

fares — Child Entity — Fare (thuộc Flight)

Có ID và vòng đời mức giá riêng; trong thiết kế đề xuất, giá được cập nhật qua Flight Aggregate.

NoFieldData TypePKFKUNNNDescription
1idUUIDXXXUnique identifier for each fare.
2flight_idUUIDXXID referencing the flight associated with the fare.
3fare_classStringXFare class (ECONOMY, BUSINESS, FIRST).
4base_priceDecimal(15,2)XBase ticket price for the specified fare class.
5currencyStringXCurrency code for the fare (e.g., VND, USD).
6valid_fromTimestamp with time zoneXDate and time when the fare becomes effective.
7valid_toTimestamp with time zoneXDate and time when the fare expires.

Business behavior (đề xuất): Hành vi đề xuất (gọi qua Flight): addFare(), changeFarePrice(), changeValidity(). Money >= 0; valid_from < valid_to; quyết định chính sách khoảng giá trùng.

seats — Aggregate Root — Seat

Mỗi hàng là một ghế trên một chuyến bay; chính Seat bảo vệ quy tắc giữ/đặt ghế và tranh chấp đồng thời.

NoFieldData TypePKFKUNNNDescription
1idUUIDXXXUnique identifier for each seat.
2flight_idUUIDXXID referencing the flight to which the seat belongs.
3seat_numberStringXSeat number within the flight (e.g., 12A, 12B).
4seat_classString (enum)XSeat class (ECONOMY, BUSINESS, FIRST).
5statusString (enum)XCurrent seat status (AVAILABLE, HELD, BOOKED, BLOCKED).
6held_by_booking_idUUIDID of the booking temporarily holding the seat (from Booking Service).
7hold_expires_atTimestamp with time zoneExpiration time of the temporary seat hold.

Business behavior (đề xuất): Hành vi đề xuất: hold(bookingId, expiry), confirm(bookingId), release(bookingId), block(), unblock(), expireHold(). Không cho 2 booking giữ cùng một ghế; kiểm tra owner và expiry.

flight_availability — Read Model — FlightAvailability

Tổng hợp theo (flight_id, fare_class); tối ưu truy vấn, không là nguồn sự thật cho trạng thái ghế.

NoFieldData TypePKFKUNNNDescription
1flight_idUUIDXXXID referencing the flight whose seat availability is tracked.
2fare_classStringXXFare class for which seat availability is calculated.
3available_seatsIntegerXNumber of seats currently available for booking in the specified fare class.
4class_capacityIntegerXTotal number of seats allocated to the specified fare class.

Business behavior (đề xuất): Query methods đề xuất: findByFlightAndClass(), findByFlight(), checkCapacity(). Không dùng kết quả query làm cam kết giữ chỗ; projection cập nhật khi Seat đổi trạng thái.

4. Value Objects & Enums

VO đại diện giá trị, bất biến và so sánh theo value; không tạo repository riêng. Những VO bọc ID có thể được dùng chung giữa các Aggregate, nhưng không biến các Aggregate thành một.

AirportCodeStringAirport / FlightMã sân bay 3 ký tự, kiểm tra tồn tại

Enums

5. Thành phần được gọi ở đâu?

Search (Query)

FlightController → SearchFlightsQuery → SearchFlightsUseCase (port/in) → SearchFlightsService → FlightQueryPort (port/out) → FlightQueryAdapter → Read DTO

Search nên truy vấn projection/join tối ưu; không cần hydrate toàn bộ Flight Aggregate.

Update Fare (Command)

Admin Controller → ChangeFareCommand → ChangeFareUseCase → ChangeFareService → FlightRepository → Flight.changeFarePrice → Repository Adapter → JPA

Fare là child Entity, nên thay đổi qua Flight Root.

Hold Seat (Command)

Booking Service → SeatInternalController → HoldSeatsCommand → HoldSeatsUseCase → HoldSeatsService → SeatRepository/Seat.hold → Repository Adapter → atomic DB transaction

Domain kiểm tra luật; database bảo vệ đồng thời; nhiều ghế phải all-or-nothing.

Availability (Read Model)

Seat status changed → projection updater → flight_availability → GET availability

Đảm bảo cập nhật nhất quán hoặc reconcile; không dùng availability check thay cho atomic hold.
