Payment Service – Airline Booking System

Guide triển khai Payment Service. Schema lấy đúng Group Documentation mục 2.1.3. Cổng thanh toán demo là VNPay Sandbox (redirect + IPN), không dùng mock/simulate. Aggregate, API, outbox được bổ sung cho khớp Booking, không thêm cột DB ngoài tài liệu nhóm.

0. Nguồn thiết kế — không tự bịa schema

Database đã chốt trong Group Doc: payments, refunds, outbox_events. Guide này không thêm version, paid_at, failure_reason, hay đổi create_at thành created_at. Tên cột giữ nguyên tài liệu nhóm để đồng bộ Booking (create_at / update_at).
  • Group Documentation – mục 2.1.3 Payment Service: 3 bảng.
  • Group Documentation – mục 2.2.2 Booking: POST /api/v1/bookings/{bookingId}/payment và cancel → refund.
  • Code hiện tại: hexagonal folders + class trống trong services/payment-service.
  • shared/common: CustomException, ErrorType, ErrorResponse.
Group Doc chưa viết mục 2.2.3 (aggregate/API Payment). Các enum status, method, event type và endpoint dưới đây là phần design còn thiếu, map 1-1 vào cột String/JSON đã có.

1. Scope & Assumptions

paymentsgiao dịch thu tiền
refundshoàn tiền theo payment
outbox_eventsbáo Booking sau commit
idempotency_keychống xử lý trùng
  • Một Booking PENDING khởi tạo payment; Booking không join DB Payment.
  • booking_id là UUID tham chiếu ngoài, không phải FK xuyên service.
  • Số tiền lấy snapshot từ Booking, không tin client.
  • Demo: provider = VNPAY, môi trường VNPay Sandbox. User redirect sang cổng sandbox, thanh toán bằng thẻ test VNPay. Không mock status bằng tay.
  • Nguồn sự thật hoàn tất giao dịch là IPN (server-to-server). Return URL chỉ để redirect user về app.
  • Đồng bộ Booking bằng Transactional Outbox (bảng đã thiết kế), không gọi HTTP Booking trong cùng DB transaction.
  • Kafka không bắt buộc. Outbox relay có thể HTTP sang Booking cho demo.
  • Local demo IPN cần URL public (ngrok / Cloudflare Tunnel) vì VNPay không gọi được localhost.

2. Hiện trạng code

  • Đã có bootstrap, POM (JPA, Web, Feign, Eureka, OpenAPI), port 8084, hexagonal folders.
  • Payment đang là JPA @Entity trong domain, chỉ có id — phải tách ra persistence.
  • Money, PaymentRepository, CreatePaymentCommand, CreatePaymentPort còn trống.
  • Chưa phụ thuộc shared/common.
  • Docker mới tạo booking_db, chưa có payment_db.
  • Booking domain đã có confirmPayment(), chưa có callback API.

booking_id trong Group Doc không unique. Idempotency dựa vào idempotency_key. Thanh toán lại sau FAILED = payment mới + key mới. Domain vẫn chặn tạo payment mới nếu booking đã có payment COMPLETED.

7. Domain Rules

#Rule
PR-01Payment mới luôn PENDING.
PR-02amount > 0, currency và method bắt buộc.
PR-03Cùng idempotency_key không tạo payment thứ hai — trả record cũ.
PR-04Booking đã có payment COMPLETED thì không tạo payment mới (kể cả key khác).
PR-05complete() lần 2 trên payment đã COMPLETED là no-op.
PR-06Không FAILED | CANCELLED → COMPLETED trên cùng record.
PR-07Refund chỉ khi payment COMPLETED. Currency khớp. Tổng refund ≤ amount.
PR-08Cùng refunds.idempotency_key không tạo refund trùng.
PR-09Đổi status COMPLETED/FAILED/refund xong thì ghi outbox trong cùng local TX.
PR-10Không gọi Booking/HTTP bên trong transaction DB.
PR-11Chỉ complete() / fail() sau khi verify vnp_SecureHash hợp lệ.
PR-12vnp_Amount (đã chia 100) phải khớp payments.amount; sai amount → không complete.
PR-13IPN và Return URL có thể tới cả hai: complete() idempotent, chỉ ghi outbox lần đầu.

8.3 Outbox payload → Booking nhận

Khớp contract Booking Guide: callback payment-result. Relay đọc outbox rồi gọi:

POST /internal/v1/bookings/{bookingId}/payment-result

{
  "paymentId": "uuid",
  "result": "SUCCESS",          // map từ PaymentCompleted
  "amount": 3000000,
  "currency": "VND"
}

result = SUCCESS | FAILED

RefundCompleted: Booking tự cancel sau khi gọi refund, hoặc nhận event riêng nếu nhóm chốt thêm. MVP: Booking gọi refund rồi tự cancel() khi refund COMPLETED đồng bộ trong response; outbox vẫn ghi để retry nếu sau này tách async.

9. Outbox & Integration

Vì sao có outbox: Group Doc đã thiết kế bảng này. Dùng để không mất event khi Payment đã COMPLETED mà gọi Booking fail.
1. VNPay IPN (vnp_ResponseCode = 00, hash + amount OK)
2. BEGIN TX
     update payments set status = COMPLETED, provider_txn_id = vnp_TransactionNo
     insert outbox_events (
       aggregate_id = payment.id,
       type = 'PaymentCompleted',
       payload = {...},
       published = false
     )
3. COMMIT
4. OutboxPublisher (scheduler ~1s)
     select where published = false
     HTTP POST Booking payment-result
     set published = true, published_at = now()
typeaggregate_idpayload tối thiểu
PaymentCompletedpayment.idpaymentId, bookingId, amount, currency
PaymentFailedpayment.idpaymentId, bookingId
RefundCompletedpayment.idrefundId, paymentId, bookingId, amount, currency
RefundFailedpayment.idrefundId, paymentId, bookingId
Nếu HTTP Booking fail: published vẫn false, scheduler gửi lại. Booking confirmPayment() phải idempotent (đã no-op khi CONFIRMED).

Port: BookingCallbackPort. Adapter: Feign. Local URL http://localhost:{bookingPort} vì chưa có Eureka server.

10. Sequence

10.1 Create + VNPay complete

Client → Booking POST /bookings/{id}/payment
       → Payment POST /internal/v1/payments
            CreatePaymentPort (class đã có, đang trống)
            → nếu trùng idempotency_key: trả payment cũ
            → Payment.create(..., provider=VNPAY)
            → VnPayGatewayPort.buildPaymentUrl(...)
       ← paymentId + paymentUrl

Client redirect → sandbox.vnpayment.vn
User thanh toán thẻ test

VNPay → GET /api/v1/payments/vnpay/ipn
            verify hash + amount
            complete(vnp_TransactionNo) + insert outbox   // 1 TX
            respond RspCode=00
       relay → Booking payment-result SUCCESS
            booking.confirmPayment()
            Booking = CONFIRMED

VNPay → GET /api/v1/payments/vnpay/return
            cùng complete() idempotent nếu IPN chưa tới
            redirect UX thành công/thất bại

10.2 Cancel confirmed

Client → Booking POST /bookings/{id}/cancel
       → Payment POST /internal/v1/refunds
            VnPayGatewayPort.refund(...)
            payment.refund(...) + outbox RefundCompleted
       ← refund COMPLETED
       → booking.cancel()

   |                                                          refunds.status = COMPLETED)
   +--VNPay IPN/Return ≠ 00--> FAILED
